## Web Worker: что сделано на этапе 2
- **Ядро оценки ИИ** — урон по цели (`dpsAt`, `dpsAt3`) и дальность обнаружения снаряда (`warnT`, `warnR`) — вынесено в чистый модуль `src/05w-ai-kernel.ts`: без DOM и состояния боя, константы передаются при инициализации. Итог боя после выноса совпал бит-в-бит (контрольная сумма полного результата).
- **Поток `src/05w-ai-worker.ts`** загружает это ядро. `tools/worker-test.cjs`: 20 000 оценок в потоке совпали с главным потоком без единого расхождения (числа с плавающей точкой бит-в-бит).
- **Стоимость передачи снимка мира** для планировщика (кинематика, оружие, сенсоры всех кораблей, снаряды): 0,4 / 0,4 / 1,3 / 2,1 мс при 10 / 25 / 50 / 100 на сторону — в 7–35 раз меньше одного решения ИИ (около 15 мс). **По стоимости данных перенос оправдан.**
- **Что ещё нужно для переноса решений:** вынести в модуль ядра `plan2b`, `predI`, `predictCmds`, `ghostOf` и физику корабля (`ctrlStep`, `actuateMove`, `actuateTurn`, `turnPhys`). ## Web Worker: не переносил, обоснование

- План корабля (`plan2b`) читает почти весь мир боя: треки, оценки противника, снаряды в полёте, препятствия, флот, роли. Прогноз гоняет тот же `ctrlStep`, что и бой. Всё это живёт в одном большом замыкании `makeBattle` с общими изменяемыми переменными.
- **Для Worker нужно:**
  1. вынести физику корабля и планировщик в модуль без DOM;
  2. каждый шаг сериализовать снимок мира для всех занятых решением кораблей (сотни кораблей с модулями — структурное копирование дороже самих решений при 10–25 на сторону);
  3. ради детерминизма применять решение, посчитанное по состоянию t, строго в момент t + Δ. Если Worker опоздал, симуляция обязана ждать — пиков это не убирает, их убирает только распараллеливание по нескольким Worker на многоядерном процессоре.
- **Вывод:** выигрыш реален только при 4+ Worker и после выноса кода. Это перестройка архитектуры, а задание прямо запрещает переносить без измеримого результата. Сделано то, что не трогает архитектуру: кэши, бюджет кадра, честная фактическая скорость.
- **Следующий шаг:** выделить `ghost`-физику и `plan2b` в чистый модуль, затем пул Worker по кораблям с фиксированной задержкой применения.

## Пики

Пики до 0,3–0,4 с на шаг возникают, когда в одном шаге совпадают решения многих кораблей (контакт, залп, внеочередные пересмотры). Очередь «не больше N решений за шаг» пробовал: она меняет поведение и не трогает внеочередные решения, поэтому выключена (`planner.cap=0`).
